О пользовании докой

Данный документ представляет собой описание функций компилятора скриптов Fallout 2 от BIS. Для удобства навигации документ разбит на главы, которые в свою очередь разбиты на пункты и так далее. В начале каждой главы, пункта и т.д. имеется краткое описание. Перед тем, как пользоваться документом, загляните в раздел "Некоторые соглашения", где описаны используемые в документе обозначения.

Многие функции компилятора, описанные в официальном руководстве, на самом деле являются макросами от более сложных (расширенных) функций. Почти в каждом разделе имеется подраздел "Макросы", где описываются макросы от функций данного конкретного раздела. В описании каждого макроса есть ссылки на исходную функцию, а в описании исходной функции - ссылки на имеющиеся макросы.

В Приложении приведена справка по номерам характеристик, умений, кодам анимаций и т.п., которые необходимо знать для работы с некоторыми функциями.

Внимание: данные по некоторым функциям не тестировались, поэтому их описания могут содержать ошибки. Если вы обнаружите такую ошибку, пишите автору документа.

Раздел 1: Стандартные обработчики

Стандартные обработчики определяют реакцию объекта на игровую ситуацию. Некоторые обработчики задают реакцию объекта на внешние воздействия, некоторые вызваются постоянно с определённым интервалом, а некоторые - при наступлении "системных" ("движковых") событий, например, таких как загрузка или обновление карты. Для каждого обработчика в движке игры определён набор стандартных действий. При вызове обработчика в первую очередь выполняются именно эти действия. Нестандартные действия определяются в скрипте объекта. Они выполняются после стандартных. Выполнение стандартных действий можно отменить с помощью функции script_overrides. Замена стандартных действий своими часто называется перегрузкой. Не следует баловаться с этой возможностью и перегружать все обработчики подряд. Это может привести к возникновению неожиданных глюков.

Обработчики объектов

Обработчики объектов представляют собой обработчики стандартных действий, производимых с объектом в игре. Такими действиями могут быть: осмотр объекта, использование объекта и др. Возможность совершения над конкретным объектом того или иного действия оперделяется его прототипом. Например, осмотреть объект можно всегда, а использовать - только если установлен соответствующий флаг.

description_p_proc - описание. Подробное описание объекта. По умолчанию вызывается описание, заданное в прототипе объекта
Примечание:
функция должна содержать script_overrides во избежание одновременного выполнения стандартной функции

look_at_p_proc - вызывается при взгляде на объект. По умолчанию выводится имя прототипа объекта
Примечание:
функция должна содержать script_overrides во избежание одновременного выполнения стандартной функции

damage_p_proc - вызывается при нанесении объекту повреждений. Число полученных повреждений передаётся через параметр fixed_param. Внимание! Если повреждения были полностью погашены за счёт брони, то данный обработчик не вызывается!

use_p_proc - вызывается при использовании этого объекта. Для получения адреса использованного на объекте предмета используется функция source_obj. Примечание: данный обработчик не вызывается для некоторых типов предметов при работе с инвентарём!

use_obj_on_p_proc - вызывается при использовании на данном объекте другого объекта. Через параметр obj_being_used_with получает указатель на объект, который был использован

use_skill_on_p_proc - вызывается, когда на объекте используют какое-либо умение. Через параметр action_being_used получает номер умения, использованного на объекте (см. Приложение)

Обработчики криттеров

Обработчики криттеров относятся к "живым" объектам, способным двигаться, вести бой, разговаривать и т.д.

combat_p_proc - выполняется во время боя. Номер конкретного события, вызвавшего функцию, передаётся в качестве параметра fixed_param:
fixed_param = COMBAT_SUBTYPE_WEAPON_USED (1) - было использовано оружие
fixed_param = COMBAT_SUBTYPE_HIT_SUCCEEDED (2) - успешное попадание
fixed_param = COMBAT_SUBTYPE_SEQUENCING (3) - проверяется боевая последовательность
fixed_param = COMBAT_SUBTYPE_TURN (4) - начало хода
fixed_param = COMBAT_SUBTYPE_NONCOM_TURN (5) - неизвестно (используется у любимцев Мельхиора, возможно, означает ход игрока)

critter_p_proc - отвечает за поведение объекта в целом, выполняется постоянно (несколько раз в секунду). В качестве параметра получает fixed_param - урон, нанесённый криттеру в последний ход. Примечание: если в скрипте криттера данная процедура отсутствует, то могут возникать глюки, например, в качестве этого обработчика может быть воспринята первая попавшаяся процедура, которая будет выполняться несколько раз в секунду.

push_p_proc - вызывается при попытке толкнуть объект

talk_p_proc - обработчик диалога, вызывается при попытке заговорить с объектом

pickup_p_proc - этот обработчик имеет разный смысл в скриптах предметов и криттеров. В скриптах предметов он вызывается когда криттер пытается подобрать этот предмет, для объектов-контейнеров - когда криттер пытается открыть их или что-нибудь украсть. В скриптах криттеров вызывается при попытке кражи у этих криттеров

Обработчики предметов

Обработчики предметов определяют действия, выполняемые над объектами инвентаря: поднять, бросить на землю, одеть.

drop_p_proc - вызывается в скрипте объекта при сбрасывании этого объекта на землю

is_dropping_p_proc - вызывается при попытке сбросить предмет в скрипте бросающего

pickup_p_proc - этот обработчик имеет разный смысл в скриптах предметов и криттеров. В скриптах предметов он вызывается когда криттер пытается подобрать этот предмет, для объектов-контейнеров - когда криттер пытается открыть их или что-нибудь украсть. В скриптах криттеров вызывается при попытке кражи у этих криттеров

Обработчики карты

Обработчики карты содержат в себе реакцию на специфические для карт действия: загрузка, сохранение или обновление карты. Обработчики карты существуют как в скриптах карты, так и в любых других скриптах. При посещении карты сначала запускается соответствующий скрипт карты, затем вызываются обработчики карты из остальных скриптов.

map_enter_p_proc - вызывается при заходе игрока на карту. Координаты появления игрока на карте передаются функции с параметром fixed_param

map_exit_p_proc - вызывается, когда игрок покидает карту

map_update_p_proc - вызывается при обновлении карты. Обновление происходит каждые 250 игровых тиков

Скриптовые действия

Скриптовые действия представляют собой обработчики, специфичные для скриптов, такие как: действия при уничтожении скрипта, активация скрипта пространственным триггером, вызов скрипта по заранее установленному таймеру. Эти действия активируются не игроком, а самим скриптовым движком игры.

destroy_p_proc - вызывается при уничтожении объекта

spatial_p_proc - вызывается в скрипте объекта при прохождении криттера над этим объектом

timed_event_p_proc - событие по таймеру. Вызывается при срабатывании ранее установленного таймера. Функции передаётся параметр fixed_param, задаваемый в add_timer_event

create_p_proc - вызывается при создании объекта-собственника скрипта (по официальной документации - не используется)

start - в Fallout2 вызывается при первом запуске скрипта, в Fallout1 - для каждого действия
Примечания:
В Fallout1 является главным обработчиком, через который вызываются все остальные. Типы действия передаются обработчику через параметр script_action, после чего происходит вызов нужного обработчика (обычно это делатеся через if-then-else). Номера обработчиков см. в Приложении.

Переменные

Этот раздел описывает работу с переменными. В Fallout существует 2 типа переменных (за окончательное отделение мух от котлет спасибо Tehnokrat'у):

1. Сохраняемые переменные игры (сохраняются при записи игры):

  • GVAR - глобальные переменные игры (доступны из всех скриптов игры). Эти переменные задаются в файле vault13.gam.
  • LVAR - локальные переменные игры (доступны из одного скрипта). Их количество задаётся в файле scripts.lst отдельно для каждого скрипта.
  • MVAR - переменные карты (доступны из всех скриптов карты, для которой заданы). Эти переменные задаются в файлах с расширением gam и именем, соответствующем имени карты.

2. Внутренние переменные скриптовой системы (доступны в тех скриптах или процедурах скриптов, в которых описаны). Подробнее о их работе см. в разделе "Ключевые слова и специальные функции".

Примечание:
Не так давно был обнаружен интересный факт: движок иногда сам изменяет значения некоторых переменных скрипта. В частности, про переменную LVAR_Hostile (5) точно известно, что она модифицируется движком. Эта переменная отвечает за атаку криттером игрока, если игрок его чем-то "обидел": она выставляется в 2 при неудачной попытке кражи и/или при выходе из диалога через Node998 (процедура, определённая БИСовцами как "боевой выход"). Далее, в процедуре critter_p_proc, двойка превращается в единицу и криттер атакует.

Раздел 3: Интерфейсные функции

В этом разделе собрана информация о функциях компилятора скриптов, позволяющих работать с пользовательским интерфейсом. Внимание! Возможности этой части скриптовых команд ещё до конца не изучены, равно как и все последствия их применения. Потому, приступая к экспериментам, будьте готовы к "глюкам" и "падениям" игры ;-).

Общие замечания:
Цитирую ABel'я: "Единственный минус при использовании интерфейсной части движка заключается в том, что все события от мышки после обработки передаются самому фоллу, даже если скрипт обработал событие сам, и это нельзя отменить. То же самое, но по-русски: если мы сделаем окошко с кнопкой, то нажатие на кнопку будет не только вызывать заданную при создании скриптовую процедуру, но и заставлять Чузена бежать в то место карты, над которым оказалась кнопка." Конец цитаты.
Выводить графику, рисовать кнопки и т.д. можно только в собственное предварительно созданное окно, иначе игра благополучно "падает".
И ещё одно замечание. После любых изменений в окне (вывода графики, добавления кнопок и т.д.) рекомендуется "обновлять" его при помощи функции ShowWin, иначе возникают глюки. Вообще рекомендуется сначала полностью подготовить активное окно и выводить его на экран в последний момент.

Внимание! Здесь описаны только те функции, действие которых более-менее известно. Функции, о которых неизвестно ничего, кроме имени и числа аргументов, не описаны!

Примечания:

2. Интерфейсные функции для вывода текста используют не aaf-шрифты, а fon-шрифты.

Раздел 4: Ключевые слова и специальные функции

В данном разделе описываются ключевые слова, используемые компилятором, а также некоторые специальные функции. Часть ключевых слов общеизвестна и используется повсеместно, другая часть может заинтересовать исключительно скриптоманьяков вроде Den Baster'а, Raven'а или автора сих строк ;-). При помощи описанных здесь ключевых слов можно осуществлять отложенный или условный вызов функций, экспортировать функции и переменные, объявлять критические функции или критический код. Специальные функции позволяют отменять вызов функций, останавливать или отменять выполнение скриптов, а также вызывать произвольный скрипт из другого.

Примечание: в квадратные скобки [] заключены не обязательные параметры.

  • Ключевые слова
  • Специальные функции

Ключевые слова

begin...end - создаёт блок. Используется при определении тела процедуры/функции, цикла, условия. Также используется при объявлении блока переменных.
Примечания:
после блока знак ";" не ставится

if (condition) then <statement1>; [else <statement2>;] - условие
Параметры:
condition - условие. Если условие истинно, то выполняется код statement1, иначе выполняется statement2.
Примечания:
если код statement1 или statement2 содержит более одной строки (завершающейся знаком ";"), то его необходимо объединить в блок

while (condition) <statement>; - цикл
Параметры:
condition - условие. Код statement выполняется до тех пор, пока условие истинно.
Примечания:
если код statement содержит более одной строки (завершающейся знаком ";"), то его необходимо объединить в блок

procedure procedure_name - используется для объявления и определения процедуры
Параметры:
procedure_name - имя процедуры. Если после имени идёт знак ";", то это объявление. При определении процедуры код должен заключаться в блок.
Примечания:
любая процедура должна быть объявлена или определена до её первого вызова

variable variable_name [:= value]; - объявление переменной или блока переменных
Параметры:
variable_name - имя переменной
value - значение переменной. Если значение присваивается переменной при её объявлении, то оно не может содержать математических операций и/или вызовов функций.

call procedure_name [in delay | when condition]; - вызов процедуры
Параметры:
procedure_name - имя процедуры
delay - задержка в игровом времени
condition - условие (условный вызов возможен только для процедур без параметров!)
Примечания:
при вызове процедура помещается в стек. Вызов может быть отменён с помощью функций Cancel и CancelAll. Процедура обязательно должна быть объявлена или определена до её вызова. Если два вызова следуют подряд, то нет никакой гарантии, что вызванные функции будут выполнены именно в таком порядке (см. также critical). Вообще, похоже, единственная функция, которая выполняется сразу, окончательно и бесповоротно - это destroy_object. При последовательном отложенном вызове одной и той же процедуры время вызова будет заменено последним значением, процедура будет выполнена только один раз (не проверено!).

critical procedure procedure_name - используется для объявления и определения критических процедур
Параметры:
procedure_name - имя процедуры
Примечания:
код критических процедур выполнятеся строго последовательно. Если в теле критической процедуры использовать блок startcritical...endcritical, то код после endcritical не будет критическим!

startcritical...endcritical - используется для создания блока критического кода
Примечания:
код внутри данного блока выполняется строго последовательно.

export variable variable_name; или export procedure procedure_name; - объявляет экспортируемую переменную или процедуру
Параметры:
variable_name - имя переменной
procedure_name - имя процедуры
Примечания:
для использования экспортируемой переменной или процедуры в другом скрипте она должна быть объявлена как импортируемая

import variable variable_name; или import procedure procedure_name; - объявляет импортируемую переменную или процедуру
Параметры:
variable_name - имя переменной
procedure_name - имя процедуры
Примечания:
для использования импортируемой переменной или процедуры её необходимо определить как экспортируемую в другом скрипте (обычно это скрипт карты)

exit - завершает выполнение скрипта, в котором вызвана

true и false - константы (логические "истина" и "ложь")

noop - он самый :-). "Пустой" оператор.

Специальные функции

void spawn(string int_file_name) - вызывает (порождает) указанный скрипт
Аргументы:
int_file_name - путь/имя файла скрипта (int-файла), вызываемый скрипт не нуждается в прописке в scripts.lst
Примечания:
при вызове скрипта выполняется процедура-обработчик start этого скрипта. Код процедуры start выполняется последовательно до тех пор, пока не будет встречено ключевое слово exit, после чего управление будет возвращено родительскому скрипту. Все переменные и процедуры, объявленные в родительском скрипте как экспортируемые, будут доступны для импорта порождённому скрипту (за эту информацию спасибо Raven'у). Обратное не верно. Порождённый скрипт не имеет собственных локальных переменных и не получает доступа к локальным переменным скрипта-родителя. На время выполнения порождённого скрипта родительский скрипт полностью останавливается. Если в порождённом скрипте не будет ключевого слова exit, то управление к родительскому скрипту не вернётся. Порождённый скрипт ни к чему не "привязывается", start - единственный обработчик, который может выполняться в порождённом скрипте. При многократном вызове функции spawn может быть создано сколь угодно много копий одного и того же порождаемого скрипта.

void fork(string int_file_name) - вызывает указанный скрипт
Аргументы:
int_file_name - путь/имя файла скрипта (int-файла), вызываемый скрипт не нуждается в прописке в scripts.lst
Примечания:
отличие fork от spawn состоит в том, что на время выполнения вызванного скрипта родительский скрипт не останавливается, а продолжает нормально функционировать.

void exec(string int_file_name) - вызывает указанный скрипт
Аргументы:
int_file_name - путь/имя файла скрипта (int-файла), вызываемый скрипт не нуждается в прописке в scripts.lst
Примечания:
вызывает указанный скрипт, при этом скрипт, из которого данная функция была вызвана, останавливается, а новый скрипт ни к чему не привязывается, из всех скриптовых обработчиков выполняется только start. Игра слетает. На exit не реагирует.

Аргументы:
int_file_name - путь/имя файла скрипта (int-файла), вызываемый скрипт не нуждается в прописке в scripts.lst
